# ComfyUI KSampler class names vary across generation tools

## Context

The metadata scanner's ComfyUI parser relied on `class_type == "KSampler"` to find the sampler node and trace prompt connections. Images generated by the Anima tool used `class_type: "ClownsharKSampler_Beta"`, causing the parser to miss the sampler entirely.

## Insight

ComfyUI-based generation tools can use custom KSampler node class names. The reliable way to detect a sampler is by its inputs signature: any node with `positive`, `negative`, and `model` inputs is functionally a KSampler, regardless of its `class_type`. Additionally, Anima uses `PrimitiveStringMultiline` reference nodes — `CLIPTextEncode.inputs.text` is not a string but a reference `[node_id, index]` pointing to another node whose `inputs.value` contains the actual prompt text.

## Evidence

- 9 Anima images from `2026-06-03` showed `['48', 0]` as the prompt instead of the actual text
- Tracing revealed: `ClownsharKSampler_Beta.positive` → `CLIPTextEncode(6).text = ["48", 0]` → `PrimitiveStringMultiline(48).value = "masterpiece, best quality..."`
- The model name was also wrong: `CLIPLoader.clip_name = qwen_3_06b_base` (text encoder) overwrote `UNETLoader.unet_name = anima_baseV10` (actual diffusion model)
- After fixes: all 9 images correctly show prompts, model `anima_baseV10.safetensors`, sampler `multistep/dpmpp_2m`, CFG 4.0, steps 32

## Recommendation

- Detect KSampler variants by checking for `positive`, `negative`, and `model` inputs rather than matching exact `class_type` strings
- Implement a generic `resolve_text_value()` function that follows `[node_id, index]` references when extracting text from CLIPTextEncode nodes
- Prioritize model sources: `CheckpointLoader.ckpt_name` > `UNETLoader.unet_name` > `CLIPLoader.clip_name` (CLIP is just the text encoder, often a different model)
